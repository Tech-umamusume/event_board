# DESIGN: 个人活动信息看板 — 架构与细节设计说明书

> **已拍板方案**：方案 B（极薄无服务器云端管家：Cloudflare Workers + D1 账本 + R2 图片柜 + 阿里云百炼视觉模型 + 双端自适应 PWA 网页）。
> **阅读前提**：本文全程使用大白话和生活比喻，不出现任何业务代码，确保哪怕明天换一个完全不了解本项目的人来接手，也能在 10 分钟内看懂整套系统的运转逻辑。

## 1. 整体架构与模块边界（像工厂流水线一样分工）

为了防止“改一个按钮颜色把数据库搞崩”或者“换个 AI 模型把网页搞瘫痪”，我们把整套程序严格拆成 **4 个各管一摊、互不越权的独立车间（模块）**。每个车间只认门口递过来的标准包裹，不管别的车间里面长啥样。

### 四个独立模块的职责边界

1. **车间一：前台窗口（网页界面 `public/`）**
   * **只干一件事**：负责“好看、好按、好粘贴”。在电脑上接收你 `Ctrl+V` 贴进来的字和图（顺手把几 MB 的超大照片无损压小一点，省流量）；在手机上按固定三层模板把卡片画出来，点二维码放大；断网时把提前存好的本地副本端出来给你看。
   * **绝对不干的事**：绝不直接碰数据库，也绝不直接去联系 AI（防止把你的 API 密钥暴露在浏览器里被别人偷走）。

2. **车间二：门卫与总调度（路由门禁 `src/index.ts`）**
   * **只干一件事**：守在大门口查密码（没带正确口令一律拦在外面，连图片链接都看不了）；放行后看清楚前台想干嘛（是想存图？想看列表？还是想让 AI 整理？），把包裹转交给对应的内部车间。
   * **绝对不干的事**：不亲自翻账本，也不亲自写 Prompt 哄 AI。

3. **车间三：仓库管理员（存储驱动 `src/storage.ts`）**
   * **只干一件事**：全厂唯一有权碰**文字账本（D1 数据库）**和**图片储物柜（R2 存储）**的人。负责把原始文字、原图按时间顺序原封不动锁进去，或者按编号取出来、删掉传错的废件。
   * **绝对不干的事**：不关心网页长啥样，也不管 AI 整理得对不对，只管忠实存取。

4. **车间四：AI 整理员（智能编译引擎 `src/compiler.ts`）**
   * **只干一件事**：拿到仓库递过来的“原始文字 + 图片”，按死规矩打包发给**阿里云百炼视觉模型**，逼着它吐出规整的“活动卡片数据”，并顺便给每张图贴标签（哪张是签到码、哪张是展馆图）。拿到结果后做一遍格式体检，合格了再交回仓库保存。
   * **绝对不干的事**：不管用户怎么登录，不管手机怎么画界面。

> **为什么这么拆最稳？**
> * 明天你要把阿里云百炼换成 Gemini 或豆包？**只需要动车间四（改配置和几行接口）**，前台、门卫、仓库完全不受影响。
> * 后天你嫌手机界面字体太小、想换个配色？**只需要动车间一**，后端和 AI 一行不用碰。

## 2. 文件目录清单（你电脑里的真实文件夹长什么样）

整个项目放在你电脑的一个独立文件夹 `event-board/` 里。为了保持极致清爽，**不引入任何重型前端打包工具**，全部核心源码加起来只有 **8 个文件**：

```text
event-board/
├── docs/                       # [文档区] 专门放咱们聊出来的设计图纸，方便随时翻查
│   ├── SPEC.md                 # 需求宪法：做什么、不做什么、怎么算验收通过
│   ├── DESIGN.md               # 本文件：整套系统的图纸、数据格式与异常兜底方案
│   └── PLAN.md                 # 施工进度表：0.1 / 0.2 / 0.3 分阶段路线图
│
├── .dev.vars                   # [本地保险箱] 放你的百炼 API Key 和私人密码（绝不上传网络）
├── .gitignore                  # [防泄密名单] 告诉 Git 永远别把保险箱和临时缓存传到网上
├── package.json                # [工具清单] 记录项目名字和启动/部署用的快捷命令
├── wrangler.toml               # [云端说明书] 告诉 Cloudflare 怎么把代码、账本和图片柜连起来
├── schema.sql                  # [账本建表图] 一次性建好“活动主表”和“原始素材表”的图纸
│
├── src/                        # [后端工厂区] 跑在 Cloudflare Workers 上的核心逻辑
│   ├── types.ts                # [标准包裹定义] 规定前后端和 AI 之间传递数据的统一格式
│   ├── storage.ts              # [车间三：仓库管理员] 专门读写账本（D1）和图片柜（R2）
│   ├── compiler.ts             # [车间四：AI 整理员] 专门调百炼视觉模型并校验输出格式
│   └── index.ts                # [车间二：门卫与总调度] 查密码、接请求、派活、代理图片
│
└── public/                     # [前台展示区] 用户在电脑和手机浏览器里直接看到的网页
    ├── index.html              # [网页骨架与样式] 电脑工作台 / 手机作战卡 / 全屏亮码弹窗
    └── app.js                  # [前台交互大脑] 处理 Ctrl+V 粘贴、图片压缩、调接口与画卡片
```

*(注：0.3 阶段接入 PWA 离线能力时，才会在 `public/` 下额外增加 `manifest.json` 桌面图标配置和 `sw.js` 离线缓存脚本两个小文件。)*

## 3. 核心数据格式（模块之间的“标准快递箱”）

为了让四个车间鸡同鸭讲不了，大家传包裹统一用 **JSON 格式**（你可以把它理解成一张印满标准栏目的快递单，每个栏目有固定的英文代号和对应的内容）。

### 包裹一：原始素材条（你往活动里贴进去的每一条原料）
不管是文字、微信链接还是图片，进仓库后都会贴上这张统一标签，按时间顺序排队保存，永远不被篡改。

```json
{
  "id": "item_20261121_001",
  "event_id": "evt_20261121_abc",
  "type": "image",
  "content": "events/evt_20261121_abc/qr_01.webp",
  "ai_role": "ticket_qr",
  "ai_summary": "入场签到二维码，核销码 8842，需现场扫码进门",
  "created_at": "2026-11-21T10:15:00+08:00"
}
```

| 字段英文名 | 中文含义（大白话解释） |
| :--- | :--- |
| `id` | 这条原始素材的唯一身份证号 |
| `event_id` | 它属于哪一场活动（防止把 A 活动的图混进 B 活动） |
| `type` | 原料类型，只允许 3 种：`text`（纯文字）、`image`（图片）、`url`（网页链接） |
| `content` | 实际内容：如果是文字/链接就直接存文字；如果是图片就存它在储物柜里的编号路径 |
| `ai_role` | AI 识别后给图片贴的角色标签：`ticket_qr`（签到码）、`venue_map`（展馆图）、`poster`（普通海报）；刚上传还没整理时为 `null` |
| `ai_summary` | AI 对这张图的一句话文字摘要（留给后续追加资料时复用，避免每次重扫十几张旧大图） |
| `created_at` | 录入时间戳，用来判断“哪条通知更新，应该覆盖旧通知” |

### 包裹二：AI 整理出的标准卡片（百炼模型必须严格照抄的答卷）
每次点击“保存并整理”，车间四都会把原料喂给阿里云百炼模型，并死命令它**只能按下面这张模板交卷**。没有数据的栏目填 `null` 或空列表 `[]`，网页看到空列表就会自动把它藏起来。

{
  "l1_core": {

    "end_time": "2026-12-05T18:00:00+08:00",
    "time_display": "12月5日 09:00 - 18:00",
    "location_name": "深圳会展中心（福田）3号馆",
    "location_address": "深圳市福田区福华三路深圳会展中心3号馆",
    "ticket_image_id": "item_20261121_001",
    "redlines": [
      "必须带实体身份证原件刷闸机",

    ],
    "change_alerts": [
      "场地变更：已从原 2 号厅改为 3 号馆（根据最新群通知更新）"
    ]
  },
  "l2_modules": {
    "schedule": [
      {
        "time": "09:30 - 11:00",
        "title": "具身智能与运动控制主论坛",
        "location": "3号馆主舞台"
      }
    ],
    "zones": [
      {
        "zone_name": "B区 电机与电控展位",
        "highlights": "B12 宇树科技、B15 达妙科技",
        "map_image_id": "item_20261121_002"
      }

    "personal_focus": [
      "去 B15 问一下新型关节电机的通信协议与样机报价"

        "label": "官方报名小程序/回执链接",

| 板块 / 字段 | 中文含义（大白话解释） |
| :--- | :--- |
| **`l1_core`（救命首屏层）** | **每场活动必有、位置焊死在最顶部** |

| `start_time` / `end_time` | 精确的开始和结束时间（给系统算倒计时、自动归档、写日历用；如果海报只写“12月中旬”就填 `null`） |

| `location_address` | 详细门牌地址（点击“一键导航”时直接传给高德/百度地图） |
| `ticket_image_id` | 被 AI 挑出来的“入场二维码/门票原图”的编号，网页会自动把它置顶放大 |
| `redlines` | 硬性红线提醒列表（必带证件、着装、停检时间，用醒目颜色标出） |
| `change_alerts` | 临时变更警告（后来追加的通知推翻了旧信息时，专门在这里红标提醒） |
| **`l2_modules`（按需模块池）** | **有内容才显示，为空 `[]` 就彻底隐身不占地** |
| `schedule` | 多时段议程表（普通 2 小时单点讲座这里为空，大型会议/展会才点亮） |
| `zones` | 多展馆/展区路由（含展位亮点和对应的展馆平面图编号 `map_image_id`） |
| `personal_focus` | 你自己写进去的私人目标（比如想看哪家公司、想问什么问题） |
| `contacts_links` | 官网链接、主办方对接人电话/微信号（点击可直达或复制） |
| **`image_triage`（图片分诊单）** | AI 顺手交回来的图片鉴定表，仓库会把结果写回包裹一的 `ai_role` 和 `ai_summary` |

### 包裹三：发给手机/电脑网页展示的“最终成品包”
前端打开某场活动时，后台把上面整理好的卡片、你的手动修改锁状态、以及底部的原始素材打包成一份完整包裹发过去：

```json
{
  "meta": {
    "id": "evt_20261121_abc",
    "status": "upcoming",
    "version": 3,
    "compiled_at": "2026-11-21T10:15:18+08:00"
  },
  "view": {
    "l1_core": { "...同包裹二（如果用户手动改过某项，这里已经替换成用户改的值）..." },
    "l2_modules": { "...同包裹二..." }
  },
  "locked_fields": ["l1_core.location_address"],
  "pending_conflicts": [],
  "raw_stack": [
    {
      "id": "item_20261121_001",
      "type": "image",
      "url": "/api/images/events/evt_20261121_abc/qr_01.webp",
      "ai_role": "ticket_qr",
      "created_at": "2026-11-21T10:15:00+08:00"
    }
  ]
}
```

| 字段英文名 | 中文含义（大白话解释） |
| :--- | :--- |
| `meta.status` | 活动状态：`upcoming`（即将发生/进行中）或 `archived`（已过期自动归档） |
| `meta.version` | 版本号（每整理或修改一次加 1，用来让手机端判断自己的离线缓存是不是旧的） |
| `meta.compiled_at` | 最后一次 AI 整理成功的时间 |
| `view` | 最终直接拿来画界面的卡片数据（已融合你的手工修改） |
| `locked_fields` | 被你亲手改过、上了锁的字段清单（防止以后 AI 重整理时误覆盖） |
| `pending_conflicts` | 如果 AI 在新通知里发现了新地点，但你的地点字段上了锁，就把冲突放这里，让界面弹个“点击确认采用新地点”的提示条 |
| `raw_stack` | 沉在页面最底部的全部原始图文列表，供你随时点开核对原件、防止 AI 幻觉 |

## 4. 细节与异常兜底（不崩溃、不丢数据、不说天书）

### 4.1 界面怎么给用户“心理安全感”？（3 种反馈状态）

1. **正在加载 / AI 整理中（Loading 状态）**
   * **防手抖连点**：按下「保存并整理」后，按钮立刻变成灰色不可点，避免你急着连点三下把同一张图传三遍、扣三份 AI 钱。
   * **分步说人话**：按钮或顶部条实时播报进度——先显示「正在压缩并保存原图…（1/3）」，存稳后立刻切换成「原件已存好！百炼 AI 正在读图整理中，约需 5~15 秒…」。
   * **不锁死全屏**：AI 正在后台思考这十几秒，你依然可以切去查看其他已整理好的活动卡片，不会被白屏干等卡死。

2. **操作成功（Success 状态）**
   * **轻提示自动消散**：顶部弹出绿色小提示条，2 秒后自动滑走（例如：「整理完成！已自动置顶 1 张签到码」），绝不弹那种烦人的“确定”确认框打断你。
   * **手机端离线安心灯（0.3 上线）**：手机页面最顶部常驻一颗小圆点——**绿灯**代表“近期活动与签到码已存入本机，断网可看 · 同步于 今天 08:30”；**黄灯**代表“当前离线，正在看上次缓存的副本”。

3. **操作失败（Error 状态）**
   * **保住现场，绝不清空输入**：哪怕网络突然断了或者 AI 报错，你刚刚辛辛苦苦粘贴进框里的文字和图片**绝不能消失**，让你直接点「重试」就行。
   * **说清现状与退路**：绝不把 `500 Internal Server Error` 这种火星文甩脸上，而是提示：「AI 暂时开小差了（超时），但你的原图和文字已经安全存进底部原始栈，随时可看，稍后点此重新整理即可。」

### 4.2 极端异常推演与优雅兜底方案

| 突发意外场景 | 系统怎么优雅接住（绝不崩溃） |
| :--- | :--- |
| **1. 手机进地下展馆彻底断网** | 网页发现拉取云端超时（超过 2 秒），立刻自动切换读取手机本地缓存的卡片和置顶二维码原图，同时在顶部亮起黄灯提示“当前离线模式，显示的是 [某时间] 同步的数据”。 |
| **2. 粘贴了微信公众号 / 小红书链接（目标网站反爬打不开）** | **根本不去云端硬爬**（彻底避开死局）。系统直接把链接当成一条可点击的“参考入口”存进原始栈和 L2 链接栏，并在录入框下方给一句温和提示：“检测到网页链接，已存为快捷入口；如需 AI 提取详情，请把正文文字或截图粘贴进来。” |
| **3. 啥也没填就点了“保存”或“整理”** | 录入框为空且没有新图片时，保存按钮直接保持置灰不可点；如果刚建了空容器还没塞任何资料就点整理，轻提示“请先粘贴至少一段文字或一张图片”。 |
| **4. 阿里云百炼 API 报错 / 限流 / 欠费 / 吐出乱码 JSON** | ① 先把原始文字和图片存入仓库（**原料先落袋为安，绝不因为 AI 挂了导致素材丢失**）；<br>② 车间四严格检查 AI 返回的文字是不是合法 JSON；如果格式乱了，后台自动静默重试 1 次；<br>③ 依然失败则保留该活动之前的旧卡片不变，只在顶部给出清晰报错（如“API 余额不足或响应超时”）和「重试整理」按钮，底部原始栈照常可看。 |
| **5. 粘贴了 10MB 超高清大图，或手滑拖进一个 PDF / 视频** | ① **图片**：前端在上传前自动用浏览器画布将宽边压到 1600px 以内的清晰 WebP/JPEG（既保住二维码和密密麻麻的小字，又把体积压到 300KB 左右，上传秒完成）；<br>② **非图片文件**：前端立刻拦截并友好提示“V1 仅支持文字和图片截图，暂不支持 PDF/视频文件，建议截图后粘贴”。 |
| **6. 输错私人密码，或陌生人拿到了图片直链** | 接口和图片代理统一返回“无权访问”，网页自动弹出极简口令输入框；陌生人哪怕猜到图片网址，看到的也是空白拦截，绝不泄露个人二维码。 |
| **7. 贴错活动了，或者 AI 抽错了某个细节** | 原始栈里每条记录都带一个「删除」按钮（删完重新整理即可消除错误影响）；卡片上发现 AI 抽错字，0.2 阶段支持直接点字手改并自动加锁，以后重整理也不覆盖。 |
| **8. 时间模糊（如“12月中旬”）或跨多天大展** | 没精确时间的预热活动归入“即将发生”列表末尾并标注「时间待定」，不会误踢进归档；跨多天活动严格以**最后一天的结束时间**作为归档分界线，展会期间始终置顶。 |

## 5. 0.1 垂直切片（先盖哪一间“能住人的毛坯房”？）

绝对不搞“先花两周写完所有后台再写前端”的烂尾套路。我们切出最薄的一刀——**0.1 最小闭环**，目标只有一个：**在你自己的电脑上零花钱、零配域名、零绑卡，跑通“粘贴图文 → 阿里云百炼整理 → 确定性三层卡片展示 + 全屏放大二维码”的完整流水线。**

### 0.1 版本只写这 8 个文件（先盖毛坯单间）

| 序号 | 文件 | 0.1 版本里它干什么（极简范围） |
| :---: | :--- | :--- |
| 1 | `wrangler.toml` | 绑定本地模拟账本（D1）、本地模拟图片柜（R2）和静态网页目录 |
| 2 | `schema.sql` | 建好 `events` 和 `raw_items` 两张表（一步到位预留好后续版本的字段） |
| 3 | `src/types.ts` | 写死上面第 3 节定义的 3 份 JSON 数据契约 |
| 4 | `src/storage.ts` | 实现新建活动、查列表/详情、存入图文、读取原图、保存 AI 编译结果 |
| 5 | `src/compiler.ts` | 打通阿里云百炼 OpenAI 兼容视觉接口，实现图片语义分诊 + 严格 JSON 校验 |
| 6 | `src/index.ts` | 实现口令门禁 + 6 个最基础接口（建活动、查列表、查详情、传素材、触发整理、代理图片） |

### 明确排到 0.2 和 0.3 的“精装修”（0.1 坚决不碰）
* **留给 0.2（演化与控制权）**：人工手动改字段 + 自动加锁（`user_overrides`）、锁字段冲突确认条、删除错传素材、增量整理时复用旧图摘要省 Token。
* **留给 0.3（脱离电脑、真正上战场）**：PWA 桌面图标与断网离线缓存（含顶部绿灯状态）、WebCal 动态日历订阅 + 单条 `.ics` 急救导入、正式部署到 Cloudflare 云端与绑定域名。

## 6. 架构师自我审查（交接砍冗余清单）

假设明天有一个完全不懂这个项目的人来接手，我把整份设计从头到尾审了一遍，确认**已经提前砍掉了以下 5 个最容易把个人小项目拖垮的“过度设计”**：

1. **砍掉了前端全家桶打包链（React / Vue / Next.js / Webpack）**
   * *理由*：我们的界面极其克制（就是一个列表 + 一个三层固定卡片 + 一个粘贴框）。直接用纯原生 HTML + CSS + JS，**不需要装几百 MB 的前端依赖、不需要等打包编译、不会遇到版本冲突报错**，接手的人打开 `index.html` 和 `app.js` 就能直接看懂修改。
2. **砍掉了数据库 ORM 框架（如 Prisma / Drizzle）**
   * *理由*：整个系统就 2 张表、总共不到 10 条增删改查。直接写最朴素的 SQL 语句放进 `storage.ts`，比学一套 ORM 配置和迁移命令简单 10 倍。
3. **砍掉了独立的多账号注册/登录体系**
   * *理由*：这是你的私人工具，不需要“忘记密码找回邮件”“手机验证码登录”“权限角色管理”。一把藏在保险箱里的私人访问口令 + 浏览器加密凭证，5 分钟写完且足够安全。
4. **砍掉了“电脑管理后台”和“手机展示端”两套独立代码**
   * *理由*：同一份 `index.html`，通过屏幕宽度自动变形（宽屏显示录入操作台，窄屏自动切为清爽的现场作战卡），维护成本直接砍半。
5. **砍掉了云端抓网页爬虫**
   * *理由*：微信/小红书反爬极其凶猛，写爬虫属于无底洞。回归“复制粘贴文字/截图 + 链接仅作快捷入口”，用最省心的方式把稳定性拉满。

**自查结论**：目前保留的 4 个车间、8 个核心文件已经到达“再删一个就跑不通闭环”的极简极限，零多余模块，随时可以按 `0.1 垂直切片` 动工。
